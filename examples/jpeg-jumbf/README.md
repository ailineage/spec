# JPEG JUMBF example

`image-64.ailineage.jpg` is [`fixtures/data/image-64.jpg`](../../fixtures/data/image-64.jpg) with the manifest of [fixture 13](../../fixtures/valid/13-image-jpeg-jumbf.json) embedded as a JUMBF box in an APP11 segment ([REQ-0215]–[REQ-0219]):

| Field | Value |
| --- | --- |
| Marker | `FF EB` (APP11), placed after the last APPn segment of the header, or directly after SOI when there is none, as here |
| Common identifier | `JP` |
| Box instance number `En` | `0x4149`, unique among the file's JUMBF boxes |
| Packet sequence number `Z` | `1` (a manifest larger than 65 517 bytes continues in segments `Z = 2, 3, …`) |
| Superbox | `jumb` |
| Description box | `jumd`: JSON content type UUID `6A736F6E-0011-0010-8000-00AA00389B71`, toggles `03`, label `ailineage` |
| Content box | `json`: UTF-8 manifest JSON (here in JCS form) |

Removing the APP11 segment yields the original file byte for byte, so `artifact.id` is the SHA-256 of `fixtures/data/image-64.jpg`.

[`hexdump.txt`](hexdump.txt) shows the beginning and end of the segment. Generated by `make fixtures-regen`, which also checks a multi-segment round trip.

To list the marker segments before the scan:

```sh
python3 -c "import sys,struct; b=open(sys.argv[1],'rb').read(); i=2
while b[i+1] != 0xDA:
    n,=struct.unpack('>H',b[i+2:i+4]); print(i, hex(b[i+1]), n, b[i+4:i+6]); i+=2+n" image-64.ailineage.jpg
```
