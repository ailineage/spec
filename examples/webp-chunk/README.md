# WebP chunk example

`image-64.ailineage.webp` carries the manifest of [fixture 14](../../fixtures/valid/14-image-webp-chunk.json) as a top-level `AILN` chunk ([REQ-0225]–[REQ-0228]).

The source [`fixtures/data/image-64.webp`](../../fixtures/data/image-64.webp) is a simple-format lossless file (one `VP8L` chunk). Before computing the identifier, the Producer converts it to the extended format by inserting a `VP8X` chunk with the canvas size and alpha flag from the bitstream ([REQ-0226]). `artifact.id` and `size_bytes` therefore describe the extended-format file, not the source file.

| Chunk | Content |
| --- | --- |
| `VP8X` | flags `00` (no alpha, ICC, Exif, XMP or animation), canvas 64 × 64 |
| `VP8L` | the unchanged lossless bitstream |
| `AILN` | UTF-8 manifest JSON (here in JCS form), padded to an even length with `00` |

Removing the `AILN` chunk and reducing the RIFF size field by the removed length yields the extended-format file. [`chunks.txt`](chunks.txt) lists the chunks and shows the `VP8X` bytes. Generated by `make fixtures-regen`.

To inspect with libwebp tools:

```sh
webpmux -info image-64.ailineage.webp
dwebp image-64.ailineage.webp -o /dev/null   # decoders ignore the unknown chunk
```
