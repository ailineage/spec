# Contributing

Thank you for helping improve AILineage. This repository contains the specification only; implementations live in sister repositories.

## Before you start

- **Questions** — open an issue with the *Question* template.
- **Changes to normative text** — open an issue with the *Spec change proposal* template first, then a pull request that includes an ADR ([adr/README.md](adr/README.md), [GOVERNANCE.md](GOVERNANCE.md)).
- **Editorial fixes** — send a pull request directly.
- **Security issues** in the specification or the escrow model — follow [SECURITY.md](SECURITY.md), not public issues.

## Rules for spec text

- Normative statements use BCP 14 keywords (MUST, SHOULD, MAY) and carry a stable `[REQ-xxxx]` ID. New IDs are allocated in the numeric range of their section. IDs are never reused or renumbered.
- Every field of the data model appears in SPEC.md §4 with type, requirement level, semantics, example and REQ-ID, and in the JSON Schema.
- Every schema condition has a negative fixture in `fixtures/invalid/`.
- Test vectors and fixture hashes are generated by `fixtures/regen.py`, never edited by hand.
- Repository files are written in English.

## Tooling

The validator is **check-jsonschema** (Python). Lint uses **markdownlint-cli2**. The fixture generator needs only Python 3.10+ and `openssl` 3.0+.

```sh
python3 -m pip install check-jsonschema
npm install --global markdownlint-cli2

make validate      # schema x fixtures; valid MUST pass, invalid MUST fail; signatures and timestamps
make lint          # markdownlint + JSON syntax
make test-vectors  # recompute CANONICALIZATION.md test vectors
make fixtures-regen  # regenerate data, fixtures, examples and generated doc blocks
```

If the tools are not on `PATH`, pass them explicitly, for example `make validate CHECK_JSONSCHEMA=.venv/bin/check-jsonschema`.

`make fixtures-regen` reuses existing signatures and timestamps when the signed content is unchanged. When content changes, it requests new RFC 3161 tokens from `https://freetsa.org/tsr` (override with `AILINEAGE_TSA_URL`). Without network access it writes a placeholder token and marks the fixture with `"_note": "ts is placeholder"`; such fixtures must not be committed to `main`.

## Commits

- Use [Conventional Commits](https://www.conventionalcommits.org/): `docs:`, `schema:`, `fixtures:`, `chore:`, `ci:`.
- Sign off every commit (`git commit -s`). By signing off you certify the Developer Certificate of Origin below.
- Keep history clean: squash work-in-progress commits before review.
